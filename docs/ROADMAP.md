# ARCANE 实施路线

目标是让创作者稳定获得可继续修改、可导出、可验证的游戏项目。对标依据和细节见 [完整审查](audit-2026-10-09/ARCANE-项目审查与优化路线.md)，能力与验证边界见 [第一轮交付](implementation-2026-10-10/ARCANE-第一轮优化交付.md)。

## 已实现的基础

严格 artifact 与离线构建、共享生成预算和取消、候选修复、统一工作区、原子不可变版本、历史与恢复、发布分享和 Remix、浏览器输入对照、可选运行工具、参数编辑、30 项固定评测集及自动 CI。

本地能力状态提示和手工预置的可编辑示例已接入；评测先校验全量数据集，并将人工验收绑定具体快照及需求契约。首批 3 项真实模型请求均返回 HTTP 401，仍需有效服务凭据才能得到质量数据，见 [联调记录](local-preview-2026-10-10/README.md)。

这些工程能力不代表已测得真实模型生成质量，浏览器验收也不证明任意玩法规则全部成立。

## 下一阶段

1. **可复现集成与 staging**：持续跑临时 MySQL 空库／升级迁移、生产依赖检查及 Linux 浏览器回归；在独立环境验证 OAuth、对象读写／签名／清理，并为 QA 配置生产 OS 沙箱。
2. **质量数据**：在显式模型预算内跑 30 项固定请求，逐玩法检查数量、操作、胜负、重开与稳定性，记录成功率、延迟、修复 token 和回归率。先修高频失败，再扩功能。
3. **素材与行为组件**：资产上传／生成、引用 manifest、来源与版权、风格一致性、缓存与预算；可复用移动、碰撞、摄像机、目标、敌人和关卡组件。
4. **运行与社区**：持久可恢复任务、共享限额、成本账本、内容管理、举报与作品发现。真实用户数据决定推荐和增长工作。
5. **独立实验**：3D、多人与世界模型。分别定义控制、成本、延迟和稳定性目标，不以研究演示代替已有能力。

模型质量评测、外部服务联调和部署需要对应环境与预算；缺少数据时明确标记未验证。迁移与 CI 使用一次性数据库，不操作业务库。
