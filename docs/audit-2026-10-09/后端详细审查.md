## 认证、存储、基础设施细节

- server/_core/sdk.ts:209–227 仅检查 appId 非空，没有比较 appId 是否等于 ENV.appId。若多个应用复用签名密钥，其他应用合法签发的 token 会被接受，应验证 audience/issuer/projectId。
- server/_core/sdk.ts:174,214–217：createSessionToken 默认 name=""，OAuth callback 也允许匿名昵称，但 verifySession 强制 name 非空；无名字用户拿到 token 后仍无法登录。姓名不是认证必需字段。
- server/_core/cookies.ts:45–46：HTTP 返回 SameSite=None + Secure=false，现代浏览器拒收；OAuth nonce cookie 又强制 Secure，普通 HTTP 非安全环境不能稳定使用。应明确 HTTPS 开发入口或本地开发 cookie 策略。
- server/_core/oauth.ts:53,57 和 shared/const.ts:2 使用一年期 session；logout 只删客户端 cookie，无服务端撤销。应有短期 access/session 与旋转/撤销机制。
- server/db.ts:22–25、server/_core/sdk.ts:314–317：每次请求更新 lastSignedIn，默认重算 role；曾手动授予的非 OWNER admin 会被下一次请求写回 user。增加 lastSeen 节流，更新用户信息不要隐式重置权限。
- server/_core/context.ts:16–20 把所有认证异常变成匿名，DB/上游故障与无登录混淆；公共生成在认证故障时仍继续消费额度。
- server/storage.ts:43,61,86 和 server/db.ts:104–110 的 fetch 同样无 deadline，加载版本无并发限制/校验 hash。
- drizzle/schema.ts 只有 users/projects/versions/messages/files/builds。没有 jobs、quota/billing ledger、assets、publishes/shares、play sessions、reports/moderation、analytics/leaderboards/multiplayer sessions。
- maps、transcribe、dataAPI、heartbeat、imageGeneration 大多是 Manus 模板基础设施，当前路由没有把语音/地图/图像资源编排接入生成主流程；不能把 helper 的存在算作产品能力。voiceTranscription.ts:97–111 如后续暴露用户 URL，需要 SSRF/流式大小限制，因为下载完才检查 16MB。当前不是已可触发的公开漏洞。
- package.json 缺 lint、安全扫描/覆盖率/CI脚本；Vitest include 只包括 server 下测试。认证范围只有 logout mock，branding 测试绑定真实部署 env 和固定 logo URL；缺 OAuth state/session、对象权限、数据库并发/故障补偿、SSE取消、请求预算、生产部署验收。

## 优化顺序及平台对标

近期，先形成能上线的小闭环：完整迁移/生产启动、统一生成入口和额度、存储 ACL、路径/size 限制、原子版本保存、真实取消和 deadline。建立 30–100 个固定 prompt 基准，记录成功生成并跑通比例、首个可玩时间、修复次数、每个可玩作品成本、后续修改不破坏旧玩法的比例；不要只统计模型返回 JSON 成功。

中期，让对话修改即可玩稳定成立：Job/Worker/事件系统、可恢复任务、基于 artifact hash 的服务端 sandbox 验证、成本 ledger 和按复杂度路由模型、资产库/许可 metadata、不可变版本、差异 patch/冲突检测；加入 draft→validated→published 生命周期。使用独立资源池的 Python/browser worker，比在 Express 请求里长时间生成更合适。

再做 Google Playground 式分享与分发：用户主页、私人作品、可撤销链接分享、明确公开发布、Explore、fork/remix 与来源归属、缩略图/审核、独立游戏运行域名/CDN、游戏播放统计与反馈。不必为所有作品一开始提供实时多人；排行榜和异步社交先落地，实时多人需要房间、权威服务器/状态同步/防作弊以及生成模板约束，不能让 LLM 随意生成客户端代码就宣称支持。优先一个品类质量稳定后，再扩充。

长期：多人/UGC 的信任模型、版本兼容资产体系、流量成本/缓存、A/B difficulty tuning、创作者生态和收益分配。物理世界视频生成属于另一条基础设施和研究路线，不建议将当前代码生成产品直接重写成世界模型。
