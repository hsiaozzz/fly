## 当前真实能力

- 生产接口 `server/routers.ts:29-30`、`server/game/streamRoute.ts:48,73` 调用 `freeGenerate/freePatch`。
- `freegen.ts`：确定性关键词绕过澄清或一次 Planner LLM；再让同一 LLM 输出 JSON 内完整 HTML/JS 代码；文件树边界检查；9 条源码正则检查；最多 2 次可玩性修正；返回工作台。
- 生成方式偏向 Canvas2D/DOM、内联 `index.html`、约350行、8,000输出 tokens；无美术/音频/3D资产产出流程，无玩法验收契约、自动浏览器游玩、视觉评审、评测集、项目检索或引擎能力注册。
- “Planner / Game Creator / Validator” 是 trace 标签和顺序函数，不是具有独立工具/记忆/执行环境的多智能体系统。
- GameSpec/Phaser 编译器、模板修正、针对 config 的 patch 留在源码，但没有生产路由调用；`motoSpec.ts` 无调用点。
- journey、伪3D赛车、Dave 潜水经营是独立实验或模板，不证明自然语言生成平台可以生成同等品质。

## 最高优先级问题（具体位置、触发、影响）

1. **Build passed 与可运行事实无关。** `server/game/freegen.ts:415,451` 无条件赋 `status: "passed"`；`validation.failures` 非空仍返回成功。用全局 `fetch` stub 返回仅 `<p>hello</p>`：经过2次请求，3项源码门禁失败，但 build 为 passed。应区分 `artifact_valid / parsed / bundled / runtime_verified / requirements_verified`，失败不得标可玩成功。

2. **非法/截断 JSON 没有承诺的第二次重试。** `freegen.ts:308-315` 中 `askOnce/parseJsonObject` 抛错未 catch；第二次循环只有解析成功但文件校验失败才到达。stub 返回 `{bad JSON`，fetch calls=1 即抛异常。`finish_reason` 也从未检查。

3. **JSON 修复不理解字符串和栈。** `freegen.ts:84-95` 数所有 `{[}]`，把代码字符串内括号当 JSON 结构；固定先补 `}` 再补 `]` 不遵守嵌套闭合顺序，最多6符。不能修复截断字符串，常见完整代码大输出风险未解决。改为结构化输出/工具文件写入、分文件预算、明确截断续写；不要修复半段源代码后当完整游戏。

4. **第一次校验错误被丢弃。** `freegen.ts:317-319` 先取 `validateArtifact(parsed).artifact`，忽略 `.valid/.errors`，再校验已经被过滤过的文件树。直接校验 unsafe `../bad` 返回 valid=false；stub 通过相同 payload 生成则只保留 index 并 passed。坏路径不会写到父目录，但非法/重复/超限产物被静默裁剪，拒绝和重试策略失效。

5. **修复器没有拿到待修复代码。** `freegen.ts:336-342` 虽接收 `candidate`，prompt 只包含原始用户请求和缺陷；生成模式完全不附 current artifact。模型无法精确修补上一版，只能重写；patch 修复还在 `:352` merge 回原始 existing，不是上一轮 candidate，丢失先前修复。应把当前文件、诊断定位、base hash和变更操作给修复器。

6. **空 patch 被当成功，删除/重命名不可表达。** `freegen.ts:266-280` `.artifact` 总有值，`{files:[]}` 会 merge 原项目并成功；说明注释“nothing usable => null”不成立。模型只提供 changed files，但 merge 只做 upsert，永不删除旧文件；不传既有 title/controls 元数据，默认标题 Updated Game、controls 清空。stub 已复现 empty patch accepted title=Updated Game。改为显式 operations + revisionId/base hash、非空有效修改、事务预览diff。

7. **静态门禁既可漏报又会误报。** `sourceGates.ts:59-63,85-87,102,117-119` 检测存在字符，并包括未引用 JS/TS 文件、注释、字符串，没有 JS/HTML AST 和依赖图。comment 内写 `requestAnimationFrame addEventListener("keydown",()=>{})` 再加入非法 JS，runSourceGates 仍 ok=true（已复现）。事件驱动棋类、卡牌、DOM谜题无需持续游戏循环，却在 `:100-110` fail；渲染容器只认指定 ID/getElementById，不认合法 querySelector/引擎 API；CSS sibling完全不参与 responsive 检查。应先解析、验证可达依赖，再按玩法能力检查，运行时决定真实可玩性。

8. **运行探针不能验证输入因果。** `runtimeProbe.ts:245` `inputMotion > MOTION || idleMotion > MOTION` 让纯自动播放动画也通过输入；VM 模拟无任何事件响应的不断变色画布，5项全pass。`:176-184` keydown/keyup立即连续发生，游戏按帧读取键状态时完全看不到按住；ArrowRight 的 `key` 被错误生成 right（标准应 ArrowRight），还重复派发到 window；点 canvas 不命中覆盖DOM开始按钮。应独立验收副本中使用真实 Playwright鼠标/键盘，等待多帧，参考预期状态而非画面运动猜输入。

9. **探针本身漏早期错误并干预试玩。** `runtimeProbe.ts:79,288-291` 在游戏脚本后注入，前面语法/同步执行异常发生时监听尚未注册，no_errors 可pass。它自动点击/发键会推进、重启或失败用户正在玩的游戏；CPU无限循环则探针永远不回报。应页面启动前监听，浏览器外部超时/watchdog，独立测试实例。

10. **探针消息校验不安全且不可靠。** `runtimeProbe.ts:63-69` 仅检查 typeof report==object，null也接受（已复现）；checks/errors/status/size均不验证。画布fill算法只统计亮度>8，纯黑主题/纯色背景的“有画面”含义不可靠；DOM只用节点数>5和前2000字innerText，纯CSS动画/空间移动不计，6个空节点就当渲染成功。跨域/WebGL/SVG无法采样就 warn，不能宣称验收过3D。

11. **当前源码 journey 引擎无法解析，旧 demo 掩盖它。** `shared/game/journeyEngine.ts:227` 孤立 `var _decl = {` 后面直接 `var out=null`；`new vm.Script(JOURNEY_ENGINE_JS)` 确认 SyntaxError Unexpected identifier out。所有型检过，因为是字符串；runSourceGates(compileGameProject(journey)).ok=true，亦无法发现。`tools/smoke-journey.mjs:13` 读取已提交旧 demo，旧 HTML 没坏语句，测试通过并不覆盖当前源。必须从源码在临时目录生成再冒烟，并对所有内联JS解析、校验demo与源一致性。

## 推荐架构与落地顺序

### 先做到每次生成可信，再扩内容

P0：修build状态和parse重试；统一artifact schema和规范化paths；禁止静默丢文件；输出基于revision的patch操作；加入AST语法/依赖检查；生成任务真正发阶段进度，传AbortSignal/超时/预算。移除/隔离未接生产且不可靠模板，修共享引擎并让demo从同源临时生成后测试。证据串起 promptId→generationId→revision→build→probe→requirements，不以trace文案冒充实测。

P1：隔离浏览器worker + VFS打包（真实HTML/JS/CSS/图片/字体相对路径、ESM和npm依赖支持）；真实浏览器先parse/load/start/play/fail-or-win/restart两次，监听所有console/pageerror，固定seed，移动端触屏/resize，超时与FPS/memory预算。保留用户预览实例，验收跑在副本。

P2：结构化`GameDesign`用于意图和验收，不回退只有三模板。记录题材/视角/实体/动作/核心循环/具体数字/胜负/输入/风格，生成每个requirement的可执行contract；引擎能力适配Canvas/Phaser/Three，常用移动/碰撞/相机/HUD/菜单/音频组件复用，而非350行模型反复实现所有细节。修复针对diagnostic→file→line→contract，只改相关模块。

P3：资产系统：风格参考/角色一致性→spritesheet/tilemap/UI/音频/2.5D或glTF，管理assetId/version/license/尺寸/碰撞/动画切片；资源加载与回退。图像、3D资产、动作和代码不同阶段预算，不塞进同一个JSON字符串。代码状态和可导出可编辑工程仍是核心优势。

P4：评测与作品闭环：固定50-100类真实prompt与修改任务，每类多个seed；衡量可启动/核心玩法匹配/开始到结束/修改回归/下载独立运行/首次可玩时间/平均成本/失败恢复率/视觉评分。自动指标不能代替真人乐趣，真人试玩反馈明确入评分。发布分享/remix接成作品循环后，再扩3D和世界模型API，不自研大世界基础模型。

应竞争的是“想法变可编辑、可持续修改、真实可玩的作品”的闭环。Google世界模型的实时视觉生成与可下载源代码游戏是不同技术路线；前者的视觉/持续世界/交互想象可作体验目标，不能用‘增加模型或提示词’假装获得同类底层能力。
