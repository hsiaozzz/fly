# ARCANE 界面与创作额度支付

2026-10-10。本轮重做创作首页、工作台、探索和游戏页面，并加入用户购买创作额度／套餐的支付宝网页收款代码。首页集中展示描述输入、本地可试玩示例与真实草稿；作品默认打开预览，源码、参数、检查和游戏文档按需切换。原有编辑、保存、版本、发布、Remix 与 ZIP 导出流程继续使用同一游戏快照。

本机体验地址：<http://localhost:3000/>。点击「体验示例」可在模型服务不可用时试玩、编辑和下载；点击「创作额度」打开套餐页面。付款返回页为 <http://localhost:3000/billing>。

## Stitch 与设计来源

用户要求使用 Google Stitch，并指定「电脑」插件操作浏览器。本会话没有 Stitch 连接器；电脑插件在初始化前被环境错误阻断：`sandboxCwd is not a local file URI: file:///mnt/e/code/arcanegame`，重置后仍失败。**当前 UI 是仓库组件、CSS 和本地 SVG 实现，不是 Stitch 生成稿。** 没有读取或上传用户浏览器中的资料。

## 支付状态与规则

使用[Vibe Pay](https://aipay.alipay.com/docs/vibe-pay.html)的独立「基础收款能力」，采用官方 SDK、RSA2 通知验签与服务端交易补查。合作平台的「智能收款套件／即刻收」不在本次接入范围。

- 只有服务器发布的套餐价格可以创建订单，金额使用整数分；浏览器不能选择到账额度。
- 登录用户通过自己的订单打开支付宝签名表单，只有服务端核验真实付款后才发放额度。回跳参数、本地缓存与页面消息不授予额度。
- 订单、余额、流水和通知幂等记录在同一 MySQL 事务中提交；沙箱与正式环境、不同应用的账户隔离。
- 每日免费次数优先；耗尽后预占 1 个购买额度。生成或修改完成且源码检查未失败才结算；澄清、失败、源码检查失败和取消释放预占。购买额度仍受全局 token、日次数和并发限制。
- 数据库等待期间的取消会回滚扣次。数据库提交与网络交付不能原子完成：提交后若连接立即断开，可能已经扣次而浏览器未收到结果；当前没有持久任务结果恢复页面，需要人工核对。这是后续应补充的恢复流程。
- 进程中断的预占在 15 分钟后由余额查询或新任务恢复。免费次数／平台容量仍是单进程内存限流，多副本部署前需要共享限流。
- 关闭新售卖或撤下套餐价格不删除已有权益；完整商户配置保留时，可继续确认在途订单和消费已购额度。

当前商户未配置，因此真实购买关闭，建议套餐明确标为尚未售卖。尚未提供退款、退款冲账或自动续费。配置方法、官方依据和商户联调步骤见 [支付接入说明](../payment-integration.md) 和仓库 `.env.example`。新迁移 `drizzle/0006_payment_credits.sql` 只在一次性 CI 数据库验证，本轮未操作业务数据库或执行真实交易。

现有真实模型联调仍有 HTTP 401，未进行新的付费模型重试。界面、mock 支付、源码与数据库测试通过，均不代表真实商户、OAuth 或模型供应商已经联通。
